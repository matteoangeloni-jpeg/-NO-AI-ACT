Ordenes planificadas: npm run typecheck, npm test, npm run build, npm run audit:seo, npm run check:dist, npm run smoke:guided-inquiry, npm run smoke:release-cases and npm run smoke:final-modes. Las pruebas técnicas no constituyen validación educativa ni certificación de accesibilidad.

Orden de terminación requerida. Escriba todas las herramientas de mediación, componentes, materiales de transferencia y observación antes de comenzar las pruebas. A continuación, ejecutar toda la suite, la cobertura de humo guiado de 14 casos × tres idiomas y seis perfiles de diseño, Study 02 cobertura de dos formas × tres idiomas × PRE/POST, y retrocesos de catálogo/modo. Una corrección que surja durante las pruebas requiere la repetición de las comprobaciones pertinentes antes de la entrega. Los exámenes utilizan datos sintéticos y no proporcionan pruebas de aprendizaje humano.

La telemetría existenteMetrics.ts incluye contradictorioEvidenceRecognizado, derivado de la apertura de ciertas categorías de exposiciones. Su nombre puede implicar más de lo que demuestra el comportamiento. En Study 02, tratarlo como un proxy de exposición técnica; no inferir el reconocimiento de contradicción sin la explicación del participante. Este aumento no cambia el esquema de telemetría.

## Human protocol still to conduct

Contratar principiantes y participantes experimentados con el consentimiento para la observación y las notas. Una iteración inicial con 5-8 participantes por perfil puede revelar obstáculos sin estimar la eficacia. Record CEPAJe contexto, idioma, dispositivo, asistencia, interrupciones y dificultades de lectura.

Tareas: explicar el propósito de la clasificación, formar una hipótesis, encontrar y conectar dos fuentes, identificar una alternativa, escribir antes de firmar, releer después de la retroalimentación y justificar la revisión o confirmación. El facilitador registra el éxito independiente, el éxito con la asistencia, la no terminación, el grave error y la razón declarada. No clasificar el clic cuenta como pensamiento crítico.

Criterios de revisión de diseño. La incapacidad para salir de un diálogo, la firma accidental, la pérdida de texto dentro de una sesión o un impulso que revela la solución requiere corrección antes de ampliar el prototipo. Para entender, establecer un umbral piloto operacional, como por lo menos cuatro de cada cinco principiantes que explican la tarea en sus propias palabras. Reportar casos discordantes también. Esta es una decisión de producto, no una prueba de eficacia.

Pruebe lectores de pantalla real, dictado o transcripción mediada, navegación del teclado y toque con un teclado en pantalla. Proporcionar una ruta equivalente de respuesta oral para las personas que enfrentan barreras de escritura. Los tres idiomas requieren un examen humano antes de la contratación para Study 02.

Este es el plan de verificación metodológica original. Traductor no repite sus pruebas de humo: la corrección de localización V5.0.1 se comprueba con cheques de idiomas estáticos, pruebas de unidad y construir solamente, según lo solicitado por el propietario.
